## Definición de requisitos del proyecto

- Gestionar autenticación, sesiones, usuarios, roles y permisos.
- Administrar pacientes, profesionales, especialidades, agendas y disponibilidad.
- Permitir reserva, confirmación, cancelación y reprogramación de citas.
- Recuperar cupos liberados mediante lista de espera con control de concurrencia.
- Registrar check-in y estados del flujo ambulatorio, sujetos al proceso institucional validado.
- Incorporar notificaciones, auditoría, indicadores y dashboard operativo.
- Ofrecer portal público, portal de reservas, web operativa y aplicación móvil para pacientes.
- Aplicar seguridad, privacidad, accesibilidad, observabilidad y pruebas automatizadas.

## Descripción general del proyecto, límites y entregables clave

Desarrollo académico de una plataforma web y móvil para gestionar citas médicas y realizar el seguimiento del flujo de consulta externa, tomando como caso de estudio al Hospital de Huaycán.

- **Límites:** Comprende la gestión de citas, pacientes, profesionales, disponibilidad, lista de espera, notificaciones y trazabilidad de la atención. Excluye historia clínica completa, diagnóstico, farmacia, facturación, emergencias, integraciones oficiales y uso de datos reales.
- **Entregables claves:** Planificación del proyecto, requisitos, diagramas de procesos, diseño de base de datos y UX/UI, MVP web y móvil, pruebas de software y seguridad, despliegue académico y planes de monitoreo y mantenimiento.

## Riesgos generales del proyecto

- Falta de validación del proceso institucional real.
- Crecimiento no controlado del alcance.
- Conflictos de reserva o reasignación.
- Retrasos de integración entre backend, web y móvil.
- Exposición de información sensible.
- Decisión móvil no resuelta.
- Ajustes del calendario académico.
- Desviación del presupuesto estimado.
